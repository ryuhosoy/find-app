# ミツケル（Mitsukeru）

棚を撮った1枚の写真から、欲しい商品を「さがす」「えらんで」もらうExpoアプリのプロトタイプです。

- **フェーズ1：さがす** — 色・銘柄名などを指定すると、写真内の該当商品を枠で囲んで表示します。
  例：「緑のモンスターはどこ？」「じゃがりこはどこ？」
- **フェーズ2：えらんで** — 条件・要望を伝えると、写真内の商品から最適な1つを理由付きで推薦します。
  例：「一番カロリーが低いお菓子は？」「眠い、これに一番効くのはどれ？」

## できること

1. 写真を撮る／ライブラリから選ぶ
2. モード（さがす／えらんで）と要望をテキストで入力
3. 画像とテキストをClaude（Vision対応）に送信し、該当商品の位置（バウンディングボックス）と回答をJSONで取得
4. 「えらんで」モードでは、AIが返した商品名を `data/products.ts` の自社商品DBと突き合わせ、
   カロリー・カフェイン量などの数値をDBの値で補強（DB未登録の商品は「AI推定」であることを明示）
5. 結果画面で、写真の上に枠を重ねて該当商品をハイライト表示

## セットアップ

```bash
npm install
cp .env.example .env
# .env を開いて EXPO_PUBLIC_ANTHROPIC_API_KEY にAPIキーを設定
npm run ios     # または npm run android / npm run web
```

`.env` を編集したら開発サーバーを再起動してください（環境変数はビルド時に埋め込まれるため）。

## 技術構成

- **Expo Router**（`app/index.tsx` = 入力画面、`app/result.tsx` = 結果画面）
- 画像選択: `expo-image-picker`、送信前の縮小・圧縮: `expo-image-manipulator`
- Vision AI: Anthropic Messages API（`claude-sonnet-5`）を **tool use（Structured Output）** で呼び出し、
  `answer` / `recommended` / `matches`（それぞれ商品名・0〜1000正規化座標のバウンディングボックス・確信度）を
  必ず構造化データとして受け取る（`lib/claude.ts`）
- 結果の枠描画: 正規化座標をパーセント換算し、画像の上に絶対配置のViewを重ねる（`components/ShelfCanvas.tsx`）
- 自社商品DB: `data/products.ts`（コンビニ主要商品のカロリー・カフェイン量などの参考値と、
  AIの表記ゆれを吸収するあいまい一致ロジック）

## 既知の制約・精度リスク（要件書どおり）

- **APIキーの扱い**: プロトタイプとしてクライアントから直接Anthropic APIを呼び出しています。
  `EXPO_PUBLIC_` 環境変数はアプリのバイナリに埋め込まれ、抽出可能です。
  本番リリースでは、APIキーをサーバー側だけに置くプロキシ経由の構成に置き換えてください。
- **見た目の取り違え**: 同一ブランドのカラーバリエーション違いなど、似た商品を誤認する可能性があります。
  プロンプト側で「パッケージの文字・ロゴまで確認する」よう指示していますが、100%ではありません。
- **数値のハルシネーション対策**: 栄養成分などはAIの一般知識だけに頼らず、`data/products.ts` の自社DBで
  裏付けが取れた商品には「🗄️ 自社DB確認済み」、取れなかった商品には「🤖 AI推定（参考値）」と明示しています。
  DBは現在プロトタイプ用のシード値（十数商品）のみなので、実運用では商品情報APIや自社マスタに差し替えてください。
- **バウンディングボックスの精度**: Claudeは専用の物体検出モデルではないため、枠がやや大きい／ずれることがあります。
